# 和太鼓リズムゲーム 並列作業分解・検証計画

## 1. 方針

仕様書で定義したリズムゲームを実装へ進めるため、作業を互いに干渉しにくい最小単位へ分割する。各担当はインターフェース、データ形式、完了条件を先に合意し、画面・ゲームロジック・アセット・検証を並列に進める。

## 2. チーム分担

| 担当 | 主な責任 | 成果物 |
| --- | --- | --- |
| 進行管理 | タスク順序、依存関係、受け入れ確認 | 進捗表、レビュー記録 |
| UI 担当 | 各画面のレイアウト、操作導線、レスポンシブ対応 | 画面コンポーネント、UI 状態遷移 |
| ゲームロジック担当 | 譜面再生、入力判定、スコア、ゲージ | 判定エンジン、スコア計算 |
| データ担当 | 楽曲 JSON、譜面 JSON、保存データ | スキーマ、サンプルデータ、ローダー |
| アセット担当 | 背景写真、ジャケット、効果音、差し替え手順 | `assets/` 構成、命名規則、差し替えガイド |
| QA 担当 | バグ確認、回帰テスト、操作確認 | テストケース、バグ票、修正確認 |

## 4. 並列進行グループ

### グループ A: 土台作成

- 対象: T01、T02、T07、T08、T03
- 目的: 画面、入力、データ、背景のインターフェースを先に固定する。
- 完了後にほぼ全タスクが並列化できる。

### グループ B: UI 実装

- 対象: T04、T05、T06、T11、T15、T16、T19、T20、T21
- T11 と T15 はゲームロジック担当の T10、T13、T14 と接続するまではモックデータで進める。

### グループ C: ゲームロジック実装

- 対象: T10、T12、T13、T14、T17、T18
- UI に依存しない純粋関数として作り、単体テストを先に用意する。

### グループ D: データ・アセット整備

- 対象: T09、T22、T23
- サンプルデータは UI とロジックの接続テストに使えるため、早めに提供する。

### グループ E: 検証・修正

- 対象: T24、T25、T26
- 各グループの完了ごとに小さく検証し、最後に通しテストで残バグを確認する。

## 5. 推奨実装順

1. T01、T02、T03、T07、T08 を最初に完了する。
2. UI 担当はモックの楽曲・譜面・リザルトで T04、T05、T06、T19、T20 を並列実装する。
3. ゲームロジック担当は T10、T12、T13、T14、T17、T18 を UI から独立して実装する。
4. データ担当は T09 と T22 を実装し、実データで UI とロジックを接続する。
5. T15、T16、T21 を統合し、ゲーム開始からリザルトまでを接続する。
6. QA 担当が T24、T25、T26 を実施し、見つかったバグを該当担当へ戻す。

## 6. バグ確認チェックリスト

| 観点 | 確認内容 | 修正担当 |
| --- | --- | --- |
| 画面遷移 | ホームから全主要画面へ進み、戻れるか | UI 担当 |
| 選曲 | 楽曲切替時にタイトル、BPM、ジャケット、プレビューがずれないか | UI 担当、データ担当 |
| 難易度 | 存在しない譜面を選べないようになっているか | UI 担当、データ担当 |
| 背景 | 指定画像がない場合にデフォルトへフォールバックするか | アセット担当 |
| 入力 | 面と縁のキーが正しいノーツ種別にだけ反応するか | ゲームロジック担当 |
| 判定 | ±35 ms、±80 ms、±120 ms の境界値で結果が正しいか | ゲームロジック担当、QA 担当 |
| スコア | 良、可、不可、連打でスコアとコンボが正しく更新されるか | ゲームロジック担当 |
| リザルト | フルコンボ、全良、ランク、自己ベスト更新が正しく表示されるか | UI 担当、ゲームロジック担当 |
| スペシャル | 条件未達成時にボタンが出ず、達成時だけ遷移できるか | UI 担当、ゲームロジック担当 |
| 保存 | 設定、最高記録、解禁状態が再起動後も残るか | データ担当 |
| 音量 | BGM、効果音、マスター音量が独立して調整できるか | UI 担当 |
| 操作不能 | 一時停止、曲終了、戻る連打で固まらないか | QA 担当 |

## 7. バグ修正ルール

1. バグを見つけたら、再現手順、期待結果、実際の結果、使用データ、発生画面を記録する。
2. 影響範囲が 1 タスク内なら担当者が即修正する。
3. UI とロジックの境界など複数担当にまたがる場合は、入力値と出力値を先にログで固定してから修正する。
4. 修正後は同じ手順で再テストし、関連する単体テストまたは画面遷移テストも実行する。
5. スペシャル画面解放、保存データ、背景フォールバックは回帰しやすいため、毎回リリース前に確認する。

## 8. 受け入れ条件

- ホーム、選曲、難易度選択、ゲーム、リザルト、スペシャル、設定の全画面が仕様どおり遷移する。
- 背景写真をファイル差し替えまたは設定変更で反映できる。
- 1 つ以上のサンプル楽曲を最後までプレイできる。
- リザルトに応じてスペシャル画面ボタンの表示有無が変わる。
- ホームへ戻る操作がリザルト画面とスペシャル画面の両方から可能である。
- QA チェックリストの重大バグが 0 件である。
